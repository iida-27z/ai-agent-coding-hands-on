- **対象ブランチ**: `feat/janken-console-app`

## 1. 要件定義サマリー

### 1.1 概要
ユーザーがコンソール上でコンピュータと対戦できる対話型のじゃんけんゲームアプリケーション（Java 25 / Maven）を構築します。

### 1.2 目的・背景
標準入力を用いたインタラクティブなコンソールゲームの実装を通じて、Java 25およびTDD（テスト駆動開発）アプローチを用いたクリーンなアーキテクチャ設計とドメイン分離のプラクティスを実証します。

### 1.3 機能要件 (Functional Requirements)

- **FR-1: 手（Janken Hand）の表現**
  - じゃんけんの手として「グー（ROCK）」「チョキ（SCISSORS）」「パー（PAPER）」を提供する。
- **FR-2: プレイヤー入力機能**
  - ユーザーはコンソール入力（数値または対応キー: 1=グー, 2=チョキ, 3=パー, 0=終了など）を通じて手を選択できる。
  - 無効な入力（数値以外の文字列、指定範囲外の数値）に対しては適切なエラーメッセージを表示し、正常な値が入力されるまで再入力を求める。
- **FR-3: コンピュータの手の決定**
  - コンピュータはランダムに「グー」「チョキ」「パー」を選択する。
- **FR-4: 勝敗判定ロジック**
  - プレイヤーの手とコンピュータの手を比較し、「勝ち」「負け」「引き分け（あいこ）」を正確に判定する。
- **FR-5: ゲーム結果表示**
  - プレイヤーの手、コンピュータの手、および判定結果（勝利 / 敗北 / 引き分け）をコンソール上に分かりやすく表示する。
- **FR-6: 繰り返し対戦機能**
  - 1回の対戦終了後、ゲームを継続するか終了するかをユーザーが選択できる。
- **FR-7: 戦績・スコア記録**
  - セッション中の対戦成績（通算勝負数、勝利数、敗北数、引き分け数、勝率）を記録・管理し、対戦終了時またはリクエスト時に一覧表示する。

### 1.4 非機能要件 (Non-Functional Requirements)

- **NFR-1: 実装技術スタック**
  - プログラミング言語: Java 25
  - ビルドツール: Apache Maven
  - テストフレームワーク: JUnit 5 (JUnit Jupiter)
- **NFR-2: テスト網羅性と品質**
  - ドメインロジック（勝敗判定、手の一致・比較、スコア計算）に対する単体テストを厳格に作成し、高いカバレッジを維持する。
- **NFR-3: 設計・保守性**
  - ドメインモデル（勝敗・手・スコア）とコンソールUI / 入出力処理（CLI制御）を明確に分離し、変更容易性を確保する。
- **NFR-4: エラーハンドリング・堅牢性**
  - 想定外の入力や標準入力のエラー発生時においてもアプリが異常終了（クラッシュ）しない例外処理を行う。

## 2. タスク計画（開発ロードマップ）

開発を最小限のイテレーション単位（Todoリスト）に分割し、優先度および完了条件を定めます。

### タスク一覧

| タスクID | タスク名 | 優先度 | イテレーション / カテゴリ | 完了条件 (Acceptance Criteria) |
|---|---|---|---|---|
| **TASK-1** | Mavenプロジェクト初期化 | 高 | Project Setup | Java 25 / JUnit 5 が設定された `pom.xml` とディレクトリ構造が準備され、`mvn clean compile` がエラーなく完了すること。 |
| **TASK-2** | じゃんけんの手と勝敗判定コアロジックの実装 (TDD) | 高 | Domain Model | 手の列挙型/クラス、勝敗判定クラスが実装され、全ての全手組み合わせ（9通り）および例外系テストがJUnitで成功すること。 |
| **TASK-3** | スコア・戦績管理機能の実装 (TDD) | 中 | Domain Model | 対戦結果の累積（勝ち/負け/引き分けカウント）および勝率計算を行うスコア管理クラスが実装され、単体テストが通ること。 |
