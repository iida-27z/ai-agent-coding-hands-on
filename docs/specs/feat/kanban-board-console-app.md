# カンバンボード コンソールアプリ 要件定義・タスク計画書

## 1. 概要

本ドキュメントは、TODO、DOING、DONE の3つのステータスを縦に並べて表示するカンバンボードコンソールアプリケーション（Java 25 / Maven）の要件定義および開発タスク計画をまとめたものである。

ユーザーが直感的にタスクの状況を把握でき、コマンドライン上でタスクの追加・ステータス更新・削除・ボード表示が行えるシンプルなCLIアプリケーションを構築する。

---

## 2. 要件定義

### 2.1 機能要件 (Functional Requirements)

- **FR-1: ステータス管理**
  - タスクは以下の3つのいずれかのステータスを持つ：
    1. `TODO`（未着手）
    2. `DOING`（進行中）
    3. `DONE`（完了）
- **FR-2: タスク管理機能**
  - **タスク登録**: タイトル（必須）、説明（任意）を指定してタスクを登録できる。新規登録時の初期ステータスは `TODO` とする。タスクには一意の識別子（ID）が自動採番される。
  - **ステータス更新**: 指定したタスクIDのステータスを `TODO`, `DOING`, `DONE` のいずれかに変更できる。
  - **タスク削除**: 指定したタスクIDのタスクを削除できる。
  - **タスク一覧取得**: 全タスクをステータスごとに分類して取得できる。
- **FR-3: カンバンボードの縦並び表示 (UI)**
  - コンソール画面上に、以下の順序で縦方向にステータス別セクションを表示する：
    1. `=== [ TODO ] ===`
    2. `=== [ DOING ] ===`
    3. `=== [ DONE ] ===`
  - 各ステータスセクションの下に、該当するタスクの一覧（ID、タイトル、説明等）を整形して表示する。
  - 該当ステータスにタスクが1件も存在しない場合は、「(タスクなし)」等の分かりやすい案内を表示する。
- **FR-4: 対話型コンソールメニュー**
  - アプリケーション起動時に対話型のメインメニューを表示し、ユーザー入力によって各機能を実行できる。
  - メニュー項目例:
    - `1. カンバンボードを表示`
    - `2. タスクを追加`
    - `3. タスクのステータスを変更`
    - `4. タスクを削除`
    - `0. 終了`
  - 不正な入力（存在しないメニュー番号、存在しないタスクID、空のタイトルなど）に対して適切なエラーメッセージを表示し、アプリが異常終了せずにメニュー待機状態に戻ること。

### 2.2 非機能要件 (Non-Functional Requirements)

- **NFR-1: 動作環境・ビルド**
  - Java 25、Apache Maven を利用。
  - `mvn clean test` および `mvn compile` が警告・エラーなく実行可能であること。
- **NFR-2: アーキテクチャと設計方針**
  - Java 25 の言語機能（Record, Pattern Matching, Sealed Classes, Enum 等）を積極的に活用する。
  - 単一責任の原則 (SRP) およびレイヤー分離（Domain, Service, Repository, Presentation/Console）を徹底する。
  - ドメインモデルは不変性（Immutability）を重視して設計する。
- **NFR-3: テスト容易性と品質**
  - JUnit 5 および AssertJ を用いた単体テストを網羅的に作成する。
  - コンソール入出力（標準入力・標準出力）は DI（依存注入）または抽象化を行い、単体テストで検証可能な設計にする。
- **NFR-4: 保守性**
  - 全クラス・主要メソッドに日本語の JavaDoc を記述する。
  - `.agents/rules/java-instructions.md` のコーディング規約に準拠する。

## 3. カンバンボード表示フォーマット設計

コンソールへの出力イメージ（縦並び）：

```text
==================================================
                 KANBAN BOARD                     
==================================================

[ TODO ] (2 tasks)
--------------------------------------------------
  #1: ログイン画面の作成
      説明: Spring Securityを用いた認証画面
  #2: データベース設計
      説明: ER図の作成とマイグレーション

[ DOING ] (1 task)
--------------------------------------------------
  #3: APIエンドポイント実装
      説明: RESTful APIのコントローラー作成

[ DONE ] (1 task)
--------------------------------------------------
  #4: 要件定義
      説明: 仕様書とタスク分解の作成

==================================================
```

## 4. 受け入れ条件 (Acceptance Criteria)

- [ ] **AC-1**: Mavenによるビルド (`mvn clean compile`) が成功すること。
- [ ] **AC-2**: 全ての単体テスト (`mvn test`) がパスすること。
- [ ] **AC-3**: アプリを起動するとメニューが表示され、タスク追加・ステータス変更・削除・ボード表示が対話的に行えること。
- [ ] **AC-4**: ボード表示を実行した際、`TODO` -> `DOING` -> `DONE` の順序で縦方向に並んでタスクが表示されること。
- [ ] **AC-5**: タスクのステータスを変更（例: TODO から DOING）した後にボードを表示すると、該当タスクのセクションが移動していること。
- [ ] **AC-6**: 不正な入力（無効な選択肢、空のタイトル、存在しないID）に対してエラーメッセージが出力され、アプリが強制終了しないこと。

## 5. タスク一覧（開発ロードマップ）

| タスクID | タスク名 | 概要 | 優先度 | 完了条件 |
| :--- | :--- | :--- | :---: | :--- |
| **TASK-1** | プロジェクト基盤のセットアップ | `pom.xml` 作成、Java 25、JUnit 5、AssertJ の依存関係設定 | 高 | `mvn test` が実行可能な状態になること |
| **TASK-2** | ドメインモデルの実装 (TDD) | `TaskStatus` Enum、`Task` Record/クラス、`TaskId` 値オブジェクトの作成と単体テスト | 高 | ステータス定義・タスク生成・不変性更新の単体テストがすべてパスすること |
| **TASK-3** | リポジトリ・ストレージ層の実装 (TDD) | インメモリでタスクを保持・検索・更新・削除する `TaskRepository` の実装と単体テスト | 高 | CRUD操作および自動採番機能の単体テストがすべてパスすること |
| **TASK-4** | カンバンサービス層の実装 (TDD) | タスクの追加・ステータス変更・削除・ステータス別集計を行う `KanbanService` の実装と単体テスト | 高 | 業務ロジック（バリデーション含む）の単体テストがすべてパスすること |
| **TASK-5** | ボードレンダラー＆コンソールUIの実装 (TDD) | 縦並びボード文字列を生成する `KanbanBoardRenderer` および対話型UI `KanbanConsoleApp` の実装とテスト | 中 | 縦並びフォーマット出力および入出力ハンドリングの単体テストがパスすること |
| **TASK-6** | メインエントリーポイント実装と結合動作検証 | `Main` クラスの作成、対話型実行確認、エッジケース検証 | 中 | コンソール上で実際にアプリを起動し、一連の操作が想定通り動作すること |
| **TASK-7** | ドキュメント整備と品質確認 | README.md 作成、JavaDoc確認、静的解析・テスト網羅率確認 | 低 | ドキュメントが整い、ビルドおよび全テストがグリーンであること |
